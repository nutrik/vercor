# VerCOR 0.4 Deprecation Cleanup Design

**Date:** 2026-07-17
**Target release:** `0.4.0a1`
**Status:** Implemented locally; final release-gate audit and verification complete

## Objective

Remove VerCOR-owned deprecated and legacy-looking code, test compatibility
scaffolding, warning machinery, historical pre-redesign evidence, and tests
that only guard removed behavior. Preserve the supported `0.4.0a1` runtime and public API,
and keep the remaining tests focused on current behavior.

Third-party deprecations and compatibility behavior in dependencies such as
JAX, Flax, xarray, and netCDF4 are outside this cleanup boundary.

## Global constraints

- Follow `AGENTS.md`, `PROGRESS.md`, `DESIGN.md`, and `DEPENDENCIES.md`.
- Preserve supported `0.4.0a1` behavior and public signatures.
- Do not add aliases, wrappers, adapters, fallbacks, or warning suppressions to
  replace removed compatibility behavior.
- Prefer deletion to wrapping and direct supported APIs to test-only facades.
- Use idiomatic Python and apply DRY, YAGNI, and SOLID principles without
  unrelated refactoring.
- Keep JAX production functions pure, typed, immutable, and transform-safe as
  required by the repository conventions.
- Treat unclear deprecation status as uncertain: report and preserve it unless
  further evidence makes removal unambiguous.
- Use focused verification during development, then run formatting, linting,
  type checking, compilation, fast/full tests, and coverage before completion.
- Update `PROGRESS.md` after each meaningful implementation unit and commit only
  after the required verification passes.

## Removal boundary

### Historical pre-redesign evidence

Delete the intentionally retained pre-redesign evidence:

- the frozen public API contract
- the legacy public-plugin fixture
- `tests/test_v0_4_compatibility_baseline.py`

Remove their build, distribution, type-checking, release, README, design,
dependency, progress, architecture-review, and legacy migration references.
Retain the legacy migration guidance and changelog history, but make both
self-contained rather than pointing to deleted fixtures.

### Legacy-shaped component test support

Delete `tests/_component_test_support.py`. Rewrite its consumers to use direct
structural `0.4` components with `name`, `grid`, `ComponentSpec`, and `step`:

- `tests/_coverage_support.py`
- `tests/test_coupler_coverage.py`
- `tests/test_runtime_interrupts.py`

The replacements must express lifecycle setup through `LifecycleHooks`, field
declarations through `ComponentSpec`, and payloads through `SetupResult`. They
must not recreate mutable `declare_fields`, `seed_field(s)`, implicit
`initialize`, cached legacy declarations, or hidden payload injection under new
names.

Prefer small local fixtures when behavior is test-specific. Share a helper only
when it represents a current public contract and removes genuine duplication.

### Legacy-shaped output test support

Delete `tests/_output_test_support.py`. Rewrite its consumers:

- `tests/test_camulator_component_kernels.py`
- `tests/test_external_components_coverage.py`

Tests must exercise the current output contracts directly: providers,
`OutputFrame`, `OutputVariable`, the immutable accumulator boundary where a
private unit test is appropriate, and the supported writer/session path. Do not
recreate the mutable component-output adapter API with a neutral name.

### Obsolete negative tests

Delete tests whose only assertion is that a deprecated symbol, module,
argument, wrapper, warning, or alias remains absent. For mixed tests, remove the
obsolete absence checks and keep assertions for supported behavior.

Retain positive API and architecture contracts, including:

- exact supported `__all__` manifests;
- supported public signatures and return types;
- installed wheel and source-distribution behavior;
- native `0.4` public-plugin execution and strict typing;
- structural component and lifecycle behavior;
- immutable state replacement;
- current output provider, period, snapshot, JIT, and gradient behavior; and
- single-owner architectural invariants expressed in terms of current objects,
  not lists of removed names.

## Implementation flow

### 1. Remove historical evidence

Delete the pre-redesign artifacts first. Use the resulting focused
distribution/documentation failures to identify stale consumers. Update the
distribution support and boundary tests so they cover only VerCOR and the
native `0.4` plugin. Remove obsolete mypy exclusions and build commands. Update
active documentation and repository memory.

### 2. Modernize component tests

Delete the component compatibility helper, observe the affected collection
failures, and rewrite each consumer against the supported structural component
contract. Keep fixtures small and behavior-specific. Avoid a new general
mutable component builder.

### 3. Modernize output tests

Delete the output compatibility helper, observe its two affected consumers,
and rewrite them around current provider/frame/accumulator/writer behavior.
Retain the numerical and file-output assertions that validate supported model
integration.

### 4. Delete obsolete guards and audit source

Remove absence-only tests and simplify mixed tests. Scan `vercor/`, `tests/`,
`examples/`, and active documentation for VerCOR-owned deprecation warnings,
legacy helpers, compatibility aliases, deleted fixture references, obsolete
test names, version guards, and fallback branches.

Supported structural flexibility is not a compatibility shim. Preserve schema-
compatible state acceptance, optional dependency loading, logger protocols,
calendar-compatible values, and other documented current contracts. Record any
uncertain candidates instead of deleting them silently.

## Error handling and behavior preservation

This cleanup adds no new runtime error modes. Existing supported validation and
exception behavior remains authoritative. Test rewrites must assert the same
current results and failures without routing through removed facades.

If deleting a helper exposes duplicated setup in multiple tests, prefer a
small, typed current-contract fixture over copy-paste, but do not build a
general abstraction without at least two current consumers. Optional dependency
failures must remain lazy and factory-oriented.

## Verification strategy

After each implementation unit, run its focused tests and update
`PROGRESS.md`. Before the implementation commit, run fresh complete evidence:

```bash
black vercor examples tests
flake8 . --count --max-line-length=120 --statistics
mypy vercor examples tests
python -m compileall -q vercor examples tests
pytest tests/ -q --fast
pytest tests/ -q -n4 --dist=loadscope --max-worker-restart=0 --durations=25 --tb=short
pytest --cov=vercor tests/ -q -n4 --dist=loadscope --max-worker-restart=0 --durations=25 --tb=short
git diff --check
```

The implementation plan may use `conda run -n scipy` to guarantee the required
environment. Development diagnostics may use the repository's `--exit-zero`
flake8 command, but completion evidence must use the strict command above.

The obsolete test count will decrease intentionally. Coverage must remain at or
above the configured 90% gate, and supported behavior must retain direct test
coverage.

The final repository scan must report no VerCOR-owned deprecated symbols,
deprecation warning machinery, compatibility shims, deleted historical fixture
references, legacy test adapters, or tests dedicated only to removed behavior.

## Risks and controls

- **Positive coverage accidentally deleted:** rewrite mixed tests first and
  retain exact supported API manifests, signatures, and behavioral assertions.
- **Native plugin lane weakened:** keep installed native `0.4` plugin build,
  smoke, and strict-mypy checks while removing only the frozen pre-redesign lane.
- **Old semantics recreated under new names:** prohibit general mutable fixture
  builders and output adapters; review replacements against current public
  contracts.
- **Coverage falls below the release gate:** inspect deleted-test coverage and
  add direct supported-behavior tests only where a real gap exists.
- **Historical documentation becomes misleading:** retain migration and
  changelog content while removing claims that deleted fixtures remain in the
  tree.
- **Ambiguous compatibility code is removed:** preserve and report uncertain
  candidates unless active documentation or tests prove they are obsolete.

## Completion criteria

- The frozen pre-redesign manifest, plugin fixture, baseline test, and every active
  reference to them are removed.
- Legacy-shaped component and output test helpers are removed without renamed
  replacements.
- Absence-only deprecation and removal tests are gone; mixed tests cover only
  supported behavior.
- No VerCOR-owned deprecation warnings or warning wrappers remain.
- No VerCOR-owned compatibility shims, expired aliases, obsolete adapters, or
  fallback branches remain.
- Supported `0.4.0a1` APIs, examples, migration guidance, plugin behavior,
  numerical behavior, JIT, and gradients remain covered.
- Active documentation, `DESIGN.md`, `DEPENDENCIES.md`, and `PROGRESS.md` match
  the cleaned tree.
- Formatting, strict linting, type checking, compileall, fast/full pytest,
  coverage, and whitespace verification pass.
- The verified cleanup is committed to Git.
