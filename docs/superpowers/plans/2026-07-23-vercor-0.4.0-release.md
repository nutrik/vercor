# VerCOR 0.4.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare the current `refactor` branch as a locally verified, stable
VerCOR `0.4.0` release candidate without performing remote or irreversible
release actions.

**Architecture:** Treat `pyproject.toml` as the only authoritative package
version, and keep all duplicated version strings as executable release
contracts or user-facing release documentation. Change contracts first, align
metadata/docs/CI with those contracts, then validate one exact artifact bundle.

**Tech Stack:** Python 3.12+, Flit, JAX, pytest/xdist, coverage.py, Black,
Flake8, mypy, GitHub Actions, Conda environment `scipy`.

## Global Constraints

- Work in the current `refactor` branch; do not create a worktree.
- Target release is exactly `0.4.0`.
- Preserve Python support at 3.12 and 3.13.
- Preserve the six-symbol root and the documented stable extension tier.
- Do not change runtime behavior unless a validation failure proves a
  release-critical defect.
- Preserve historical `0.4.0a1` evidence where it is explicitly historical.
- Do not commit, tag, push, merge, publish, upload, or create a hosted release.
- Do not suppress warnings, weaken checks, or broaden the work into unrelated
  refactoring.
- Run every Python command through `conda run -n scipy`.
- Update `PROGRESS.md` after each meaningful release unit.
